Guide : réaliser un test de charge autorisé

Prérequis

  • Node.js installé (le serveur n'utilise que des modules intégrés).
  • Le serveur de test lancé localement : double-cliquez sur allumer.bat.
  • Une seule machine : ce serveur est destiné à votre réseau/local, jamais à une cible externe sans autorisation.

Comment lire chaque statistique

RPS — Requêtes par seconde

C'est le débit de votre application. Un test de charge vise à pousser les RPS vers le point de rupture. Observez si les RPS restent stables (bon signe) ou oscillent fortement (signe de saturation).

Latence moyenne (ms)

Temps moyen de réponse. Une latence qui monte avec les RPS indique que le serveur sature. Définissez un seuil d'alerte (par ex. 200 ms) et observez à quel débit il est franchi.

RSS — Mémoire du processus (Mo)

Quantité de RAM occupée par le processus Node.js. Une fuite mémoire se traduit par une croissance continue du RSS au fil du temps, même à charge stable.

CPU — Charge du processeur

Pourcentage d'utilisation CPU. Notez que ce serveur mesure le CPU réel (et non une charge théorique) car loadavg est peu fiable sous Windows. Atteindre 100 % indique un goulot d'étranglement côté CPU.

Uptime

Temps de fonctionnement depuis le redémarrage. Si le serveur a redémarré durant vos tests, notez pourquoi (panic, OOM, plantage).

Bonnes pratiques

  • Monter la charge progressivement : commencez par un RPS faible (ex. 1/s), puis augmentez par paliers de quelques unités toutes les 30 s.
  • Tester uniquement ce qui vous appartient : serveurs locaux, vos propres machines ou avec autorisation écrite de l'administrateur réseau.
  • Surveiller CPU et mémoire en parallèle : un goulot d'étranglement peut être CPU, I/O ou mémoire.
  • Enregistrer les résultats : notez le point de rupture (RPS maximal soutenable) et l'état des ressources.
  • Arrêter proprement : utilisez eteindre.bat pour arrêter le serveur de test.

Exemple de commande de test (curl)

Une boucle simple avec curl, dans un terminal : 

for ((i=1; i<=100; i++)); do
  curl -s -o /dev/null -w "%{http_code} %{time_total}\n" http://localhost:3000/api/health
done

Pour suivre l'état du serveur pendant les tests :

watch -n 2 curl -s http://localhost:3000/api/stats

Remplacez localhost par test-charge.local si vous avez configuré le nom local (voir la section « Accès par nom local » du serveur).
